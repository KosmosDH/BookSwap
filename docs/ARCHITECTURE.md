# Архитектура BookSwap

## Общая схема

```text
Browser
  │
  ▼
React + TypeScript
  │ REST/JSON       │ SignalR/WebSocket
  ▼                 ▼
ASP.NET Core Web API + ChatHub
  │            │             │
  ▼            ▼             ▼
PostgreSQL   Redis       Image storage
 EF Core     cache       local/Cloudinary
```

## Backend

Проект организован как модульный монолит. Для учебного проекта это проще микросервисов, но слои и предметные области разделены:

- `Controllers` принимают HTTP-запросы;
- `Dtos` определяют публичные контракты;
- `Models` описывают сущности;
- `Services` содержат инфраструктурную логику;
- `Data` отвечает за EF Core и начальные данные;
- `Hubs` реализуют чат в реальном времени;
- `Middleware` централизованно обрабатывает исключения.

## Главные сущности

- `AppUser`, `IdentityRole`;
- `Book`, `Author`, `Genre`, `BookGenre`, `BookPhoto`;
- `Favorite`;
- `ExchangeRequest`;
- `Review`;
- `ChatMessage`;
- `Notification`;
- `Complaint`.

## Основные связи

- пользователь `1:N` книги;
- книга `N:M` жанры через `BookGenre`;
- пользователь `N:M` избранные книги через `Favorite`;
- заявка связывает отправителя, получателя, запрашиваемую и предлагаемую книги;
- отзыв связан с завершённой заявкой;
- сообщение связывает отправителя и получателя.

## Безопасность

- пароли хэшируются ASP.NET Core Identity;
- API защищён JWT Bearer-токенами;
- роли проверяются на backend;
- изменение и удаление книги разрешено владельцу или администратору;
- отзыв нельзя оставить без завершённого обмена;
- Entity Framework формирует параметризованные SQL-запросы;
- React экранирует выводимый текст;
- загрузка ограничена типом файла и размером 5 МБ.

## Логика обмена

```text
Pending → Accepted → Completed
   │          │
   ├→ Rejected
   └→ Cancelled ←┘
```

После принятия обе книги получают статус `Reserved`. После отмены они снова доступны. После завершения получают статус `Exchanged`. Изменения выполняются транзакционно.

## Масштабирование

При росте нагрузки можно:

1. вынести изображения в Cloudinary/S3;
2. добавить полнотекстовый поиск PostgreSQL или Elasticsearch;
3. расширить Redis-кэш;
4. запустить несколько экземпляров API за балансировщиком;
5. подключить SignalR backplane через Redis;
6. выделить чат и уведомления в отдельные сервисы.
